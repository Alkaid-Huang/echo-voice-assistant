# 理解补课清单

> 本项目部分代码由 AI 助手生成，清单如下。
> 面试前请逐项补课：能跑 → 能改 → 能讲。
> 每一节的做法：读代码 10 分钟 → 自己动手改一个参数并观察变化 →
> 合上代码用一句话回答"这是什么、为什么这么设计、换一种做法会怎样"。

---

## 1. LLM 模块（`src/echo/llm/`）

**是什么**：把"大模型怎么调用"抽象成接口，支持本地 Ollama / OpenAI 兼容 API / 假实现。

**必须能回答**

1. 为什么 `LLMInterface.chat()` 是同步方法，异步调用却不用每个后端重写？
2. Ollama 和 OpenAI 兼容后端都走 HTTP，为什么还要分成两个类？
3. 消息列表里的 `system` 角色起什么作用？历史轮数太多会有什么代价？

**动手**：把 `conf.yaml` 的 `system_prompt` 改成"你说话像新闻联播"，观察回复风格变化。

---

## 2. TTS 模块（`src/echo/tts/`）

**是什么**：文字 → 音频文件，同样用接口 + 工厂 + 配置。

**必须能回答**

1. `MockTTS` 为什么要写一个真实的 WAV 文件，而不是返回假路径？
2. `EdgeTTSEngine` 重写了 `async_synthesize`，没有用接口默认的 `to_thread` 包装，为什么？
3. 为什么 TTS 输出是 mp3，而播放前要统一转成 16k 单声道 float32？

**动手**：换 `voice: "zh-CN-YunxiNeural"`（男声）或 `rate: "+20%"`，听差别。

---

## 3. 音频 IO（`src/echo/audio/io.py`）

**必须能回答**

1. `MicStream` 为什么用回调 + 队列，而不是在主循环里同步 `read()`？
2. 队列满了为什么选择"丢块"而不是"阻塞"？
3. 线性插值重采样有什么缺点？什么场景必须换更好的算法？

**动手**：把 `block_size_samples` 从 512 改成 1024，观察 VAD 反应速度变化。

---

## 4. 对话管线（`src/echo/pipeline/conversation.py`）

**是什么**：整条链路的编排者，也是"打断"的实现者。

**必须能回答**

1. 打断是怎么实现的？`threading.Event` 在这里承担什么角色？
2. 为什么播放要放在独立线程，而 ASR/LLM 可以 `await`？
3. 扬声器外放时为什么容易自己打断自己？真实产品怎么解决（AEC/半双工）？
4. 上下文是怎么进到 LLM 的？历史裁剪策略是什么？

**动手**：把 `barge_in` 改成 `false`，对比说话插话时的行为差异。

---

## 5. 记忆模块（`src/echo/memory/chat_history.py`）

**必须能回答**

1. 历史为什么要限制条数？不限制会发生什么？
2. JSON 文件损坏时为什么选择"清空"而不是抛异常？

## 6. VAD 扩展（`process_block` / `is_speaking`）

**必须能回答**

1. 原来的 `detect_speech` 是生成器，为什么还要拆出 `process_block`？
2. "有没有正在说话"这个状态为什么必须由 VAD 提供，而不是管线自己判断音量？

## 面试前的自测总纲

- 能在白板上画出：麦克风 → VAD → ASR → LLM → TTS → 播放，并标出哪里是异步、哪里是线程。
- 能解释：为什么四个组件都用"接口 + 工厂 + 配置"，而不是直接 new。
- 能讲出至少一个真实 bug 的排查过程（见 `docs/真实Bug笔记.md`）。
- 能说出至少一个性能数字及其测量方式（见 `benchmarks/results.md`）。
