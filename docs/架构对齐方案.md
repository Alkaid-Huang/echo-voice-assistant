# 架构对齐方案：向 D_sakiko 的分层与契约看齐

> 版本：v0.1 ｜ 更新日期：2026-09-13
> 参照研究：学习仓库 `docs/D_sakiko架构研究.md`（只学架构，不抄代码——对方是 GPL-3.0）
> 原则：**学它的分层与契约，不学它的体量与堆叠**；全部改动采用增量迁移，不做大爆炸重写。

---

## 一、目标目录结构（增量式）

保留现有可用模块，**新增**缺失的层次：

```
src/echo/
  contracts/            # 🆕 契约层：协议与错误
    protocol.py         # PROTOCOL_VERSION / CommandEnvelope / ProtocolError(code,message,retryable,details) / command_result()
    events.py           # 统一事件常量与载荷键名（thinking/tool_call/tool_result/speech/emotion/diff/test_result/state/error）
  presentation/         # 🆕 呈现层（M3 用）
    live2d.py           # Live2DVersion/Resolution/Layout/Capabilities/Error + to_dict()
    motion_groups.py    # 标准动作组 id 与情绪→动作组映射（含缺失回退规则）
    renderer.py         # 渲染器接口：本地/Web/桌面各自实现
  transports/           # 🆕 传输层（M3）
    local.py            # 本地声卡（封装现有 audio/）
    websocket.py        # WebSocket 服务端（前端/Live2D 页面对接）
  runtime/              # 🆕 运行时与存储（对齐对方的 runtime/）
    session.py          # 会话状态与元数据
    storage.py          # 落盘策略（history / facts / journal / outputs 的统一入口）
    checkpoints.py      # 检查点与回滚（编码 Agent 用）
    lock.py             # 单实例锁，防止多开写坏数据
  agent/                # 扩展
    tools/base.py       # ToolSpec / ToolRegistry（由 tools.py 迁入）
    tools/companion.py  # 时间/天气/记忆
    tools/coding.py     # view/search/edit/run（M5）
    sandbox.py          # 沙箱与权限策略（M5）
    journal.py          # 变更日志：diff + 理由（M5）
    task_state.py       # 任务状态机（M5）
  index/  eval/         # 🆕 代码库检索与评测（M5）
  media/                # ⏳ 可选收拢：vad/asr/tts/audio（最后再做，会改 import）
docs/adr/               # 🆕 架构决策记录（对齐对方的 docs/adr）
docs/术语表.md           # 🆕 领域术语（对齐对方的 CONTEXT.md）
```

## 二、迁移阶段（每阶段都可独立验收）

| 阶段 | 内容 | 交付与验证 | 风险 | 预计 |
|------|------|-----------|------|------|
| **A1 契约层** | `contracts/protocol.py` + `events.py`；管线与 Agent 的事件改为引用常量 | 新增契约测试（信封序列化、错误 retryable、事件名唯一）；现有 52 测试仍全绿 | 低 | 半天 |
| **A2 术语表与 ADR** | `docs/术语表.md`（角色/动作组/情绪/事件/双工模式等）+ `docs/adr/0001-...` 记录"为什么引入契约层" | 文档评审：术语无歧义、ADR 格式统一 | 极低 | 1 小时 |
| **A3 呈现层** | `presentation/`：Live2D 呈现契约（版本/解析状态/布局/能力/错误）+ 动作组常量与情绪映射 | 单测覆盖 `to_dict()` 与情绪→动作组回退；为 M3 提供契约 | 低 | 1 天 |
| **A4 运行时与存储** | `runtime/session|storage|lock`；把 `ChatHistory`/`FactStore` 的落盘统一走 storage | 单测：路径集中、单实例锁生效、损坏文件可恢复 | 中 | 1 天 |
| **A5 传输层（M3）** | `transports/websocket.py` + 前端页面；事件经契约下发 | 浏览器可见事件流；端到端人工验收 | 中 | 2–3 天 |
| **A6 编码工具（M5）** | `agent/tools/coding.py` + `sandbox.py` + `journal.py` + `task_state.py` + `index/` + `eval/` | 见 `docs/编码Agent集成设计.md` 的 P1–P4 | 中高 | 7–10 天 |
| **A7 媒体收拢（可选）** | `vad/asr/tts/audio` → `media/` | 全量测试通过；无行为变化 | 中（改 import） | 半天 |

**顺序理由**：契约（A1/A2）成本最低、收益最高；呈现层（A3）是 M3 的前置；
运行时（A4）让编码 Agent 的检查点/日志有地方落；传输与编码能力放在有演示之后。

## 三、与 D_sakiko 的模块对照

| D_sakiko | Echo 现状 | 对齐动作 |
|----------|----------|---------|
| `backend/protocol.py`（版本化信封 + ProtocolError.retryable） | 事件仅是 `on_event(kind, payload)` 字符串约定 | A1 引入 `contracts/` |
| `backend/live2d_presentation.py`（版本/解析状态/布局/能力/错误） | 无 | A3 引入 `presentation/` |
| `live2d_support/`（布局、规范化、runtime 适配、动作策略） | 无 | A3 + A5 |
| `chat/rolling_summary.py`（上下文压缩） | `chat_history.py` 仅按轮裁剪 | M4/M5：滚动摘要 |
| `chat/tool_calling.py`（工具 + 沙箱 + 错误回灌） | `agent/tools.py`（无沙箱） | A6 |
| `runtime/`（会话存储、音频文件、运行锁） | 落盘散在 memory/ 与 pipeline/ | A4 |
| `update/ repair/ maintenance/` | 无 | 明确不做（本地项目，靠源码运行） |
| `docs/adr/`、`CONTEXT.md` | 无 | A2 |
| 测试同位（47 个 py 测试 + 前后端测试） | `tests/` 集中 52 个测试 | 维持现状，补契约测试 |

## 四、明确不学的部分

1. **不引入 PyQt5 桌面栈与自维护 Live2D runtime 分叉**：我们走 Web 呈现（易演示、可远程、可验证）。
2. **不内置 GPT-SoVITS**：语音克隆是独立重依赖，留作 M5+ 的可选项。
3. **不做更新器/修复器**：本地源码运行的项目不需要；README 的启动脚本已够用。
4. **不写超大文件**：对方 `chat.py` 111 KB、`tool_calling.py` 82 KB，我们坚持单文件 <300 行。
5. **不抄代码**：GPL-3.0 只允许我们学习设计思路。

## 五、面试话术

> "我把项目按 D_sakiko 的分层重排：**契约层（版本化协议 + 可重试错误）、呈现层（Live2D 契约与动作组）、
> 运行时层（会话存储、检查点、单实例锁）、传输层（本地声卡 / WebSocket）、Agent 层（工具包 + 沙箱 + 审计日志）**。
> 迁移是增量的，每一步都有测试与 ADR 记录，现有 52 个测试全程保持绿色。
> 我也明确划了不做的事：不引入桌面 GUI 重依赖、不内置语音克隆、不做更新器——
> 因为本项目的定位是工程内核与可验证性，而不是功能堆叠。"
