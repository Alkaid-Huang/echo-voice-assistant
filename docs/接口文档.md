## 0. 全局约定

| 约定 | 值 | 说明 |
|------|-----|------|
| 采样率 | 16000 Hz | 由 `ASRInterface.SAMPLE_RATE` 固定，全链路统一 |
| 声道 | 单声道 | `NUM_CHANNELS = 1` |
| 采样位宽 | 16 bit | `SAMPLE_WIDTH = 2` |
| 音频数据类型 | `numpy.ndarray`，`float32`，范围约 [-1, 1] | VAD/ASR 接口的输入约定 |
| 语音段传输格式 | `bytes`（float32 原始字节） | VAD 输出到 ASR 之前的中间形态 |
| 时间单位 | 毫秒（事件回调中的 `ms`） | |
| 路径 | 相对路径以启动时工作目录为基准 | 建议在项目根目录启动 |
| 密钥 | 环境变量优先，其次读取项目根目录 `.env` | `.env` 已被 `.gitignore` 忽略，不进版本库 |

## 1. 组件接口

### 1.1 `VADInterface`（`echo.vad.vad_interface`）

| 方法 | 签名 | 语义 |
|------|------|------|
| `detect_speech` | `(audio_chunks) -> Generator[bytes, None, None]` | 流式检测，每次 `yield` 一个完整语音段 |
| `process_block` | `(audio_np, chunk_bytes) -> bytes \| None` | 处理单块，返回完整语音段或 `None` |
| `is_speaking` | `() -> bool` | 当前是否正在说话；打断检测依据，默认返回 `False` |

`audio_chunks` 的每项为 `(audio_np, chunk_bytes)` 二元组。

**内置实现**：`silero_vad`（三态状态机 + 双阈值 + 预缓冲）、`mock_vad`（逐块原样返回）。

### 1.2 `ASRInterface`（`echo.asr.asr_interface`）

类常量：`SAMPLE_RATE = 16000`、`NUM_CHANNELS = 1`、`SAMPLE_WIDTH = 2`

| 方法 | 签名 | 语义 |
|------|------|------|
| `transcribe_np`（抽象） | `(audio_np: np.ndarray) -> str` | 同步转写；输入必须 16k float32 单声道 |
| `async_transcribe_np` | `(audio_np: np.ndarray) -> str` | 默认实现：统一转 float32 后 `asyncio.to_thread` 包装 |

**内置实现**：`faster_whisper`、`sherpa_onnx`、`mock_asr`。

### 1.3 `LLMInterface`（`echo.llm.llm_interface`）

| 方法 | 签名 | 语义 |
|------|------|------|
| `chat`（抽象） | `(messages: list[dict]) -> str` | 同步对话，返回回复文本 |
| `async_chat` | `(messages: list[dict]) -> str` | 默认实现：`asyncio.to_thread` 包装 |

`messages` 采用 OpenAI 风格：

```json
[
  {"role": "system", "content": "你是 Echo……"},
  {"role": "user", "content": "你好"},
  {"role": "assistant", "content": "你好呀"}
]
```

**内置实现**：`ollama`、`openai_compatible`、`mock_llm`。

### 1.4 `TTSInterface`（`echo.tts.tts_interface`）

| 方法 | 签名 | 语义 |
|------|------|------|
| `synthesize`（抽象） | `(text: str, output_path: str \| None = None) -> str` | 同步合成，返回音频文件路径 |
| `async_synthesize` | `(text, output_path=None) -> str` | 默认 `to_thread` 包装；`edge_tts` 后端重写为原生异步 |

**内置实现**：`edge_tts`（输出 mp3）、`mock_tts`（输出短静音 wav）。

## 2. 工厂与注册

四套同构 API（VAD / ASR / LLM / TTS 各一套）：

| 函数 | 签名 | 说明 |
|------|------|------|
| `register_xxx` | `(name: str) -> Callable[[type], type]` | 类装饰器，登记后端 |
| `create_xxx` | `(xxx_type: str, **kwargs) -> XxxInterface` | 创建实例；未知类型抛 `ValueError` |

**行为约定**

- 未知类型：`ValueError("未知 X 类型: <name>，可选: [...]")`
- 真实后端延迟导入：依赖缺失抛 `ImportError` 并提示 `pip install <包名>`，不影响 mock 后端
- 工厂返回类型注解为接口类型，不泄漏具体实现

| 组件 | 内置后端 | 依赖 |
|------|---------|------|
| VAD | `silero_vad` / `mock_vad` | silero-vad, torch |
| ASR | `faster_whisper` / `sherpa_onnx` / `mock_asr` | faster-whisper；sherpa-onnx（可选） |
| LLM | `ollama` / `openai_compatible` / `mock_llm` | requests |
| TTS | `edge_tts` / `mock_tts` | edge-tts |

## 3. `ServiceContext`（`echo.service_context`）

| 成员 | 类型 | 说明 |
|------|------|------|
| `config` | `EchoConfig` | 配置对象 |
| `vad_engine` / `asr_engine` / `llm_engine` / `tts_engine` | 接口类型或 `None` | `init_*` 之前均为 `None` |

| 方法 | 语义 |
|------|------|
| `init_vad()` / `init_asr()` / `init_llm()` / `init_tts()` | 按配置创建组件；类型为 `"none"` 时置 `None` |
| `init_all()` | 依次初始化四个组件（推荐入口） |

```python
import yaml
from echo.config import EchoConfig
from echo.service_context import ServiceContext

config = EchoConfig.model_validate(yaml.safe_load(open("conf.yaml", encoding="utf-8")))
ctx = ServiceContext(config)
ctx.init_all()
```

## 4. `ConversationPipeline`（`echo.pipeline.conversation`）

### 4.1 构造

```python
ConversationPipeline(ctx, mic=None, player=None, on_event=None)
```

| 参数 | 说明 |
|------|------|
| `ctx` | 已 `init_all()` 的 `ServiceContext` |
| `mic` | 音频源，默认 `MicStream`；测试可注入假麦克风 |
| `player` | 播放函数，签名 `(path, stop_event) -> None`；测试可注入假播放器 |
| `on_event` | 事件回调 `(kind: str, payload) -> None` |

### 4.2 方法

| 方法 | 语义 |
|------|------|
| `build_messages(user_text) -> list[dict]` | 组装 `system` + 历史 + 本轮输入 |
| `respond_text(user_text) -> str` | 文本 → LLM → TTS → 触发播放，返回回复 |
| `handle_segment(segment_bytes) -> str \| None` | 语音段 → ASR → 应答；过短段丢弃 |
| `run()` | 主循环：读麦克风 → VAD → 应答；阻塞直到 `stop()` |
| `interrupt()` | 打断当前播放（幂等） |
| `stop()` | 请求退出主循环 |

### 4.3 事件回调

| `kind` | `payload` | 触发时机 |
|--------|-----------|---------|
| `listening` | `None` | 主循环启动 |
| `asr` | `{"text": str, "ms": int}` | 转写完成 |
| `llm` | `{"text": str, "ms": int}` | 回复生成完成 |
| `tts` | `{"path": str, "ms": int}` | 音频合成完成 |
| `interrupt` | `None` | 中断播放 |
| `error` | `str` | 播放失败或处理链异常 |

## 5. 音频 IO（`echo.audio.io`）

| 接口 | 签名 | 说明 |
|------|------|------|
| `MicStream` | `(sample_rate=16000, block_size=512, device=None)` | `start()` / `stop()` / `get(timeout=0.5)`；可迭代 |
| `load_audio_mono` | `(path, target_rate=16000) -> np.ndarray` | 读文件 → 单声道 float32 → 重采样 |
| `resample_linear` | `(x, src_rate, dst_rate) -> np.ndarray` | 线性插值重采样 |
| `play_audio` | `(audio, sample_rate=16000, stop_event=None, block=1024)` | 播放；`stop_event.set()` 可中断 |
| `play_file` | `(path, stop_event=None, target_rate=16000)` | 播放文件（自动重采样） |

`MicStream.get()` 超时返回 `None`；队列满时丢弃最旧块以控制延迟。

## 7. CLI 接口（`main.py`）

| 参数 | 取值 | 说明 |
|------|------|------|
| `--mode` | `check` / `llm` / `text` / `console` / `tts` / `asr` | 运行模式，默认 `check` |
| `--config` | 路径，默认 `conf.yaml` | 配置文件 |
| `--text` | 字符串 | `--mode tts` 使用 |
| `--wav` | 路径 | `--mode asr` 必填 |

各模式按需初始化组件，避免多余的模型加载：

| 模式 | 初始化的组件 |
|------|-------------|
| `check` | VAD + ASR + LLM + TTS（诊断用，最慢） |
| `llm` | 仅 LLM |
| `text` | LLM + TTS |
| `tts` | 仅 TTS |
| `asr` | 仅 ASR |
| `console` | 全部四个 |

```bash
python main.py --mode check
python main.py --mode llm --text "你好"
python main.py --mode text
python main.py --mode console
python main.py --mode tts --text "你好，我是 Echo"
python main.py --mode asr --wav samples/hello.wav
```

## 9. 异常约定

| 异常 | 触发条件 | 处理方式 |
|------|---------|---------|
| `ValidationError`（Pydantic） | 配置值非法（如 `provider="rocm"`） | 启动即失败，打印字段错误 |
| `ValueError` | `create_xxx` 传入未知后端名 | 消息含可选后端列表 |
| `ImportError` | 真实后端依赖缺失 | 消息含 `pip install` 命令 |
| `FileNotFoundError` | 模型文件或音频文件不存在 | 消息含路径与获取指引 |
| `RuntimeError` | LLM 服务不可达 / 设备推理失败 | 设备类异常触发 CPU 降级；其余上抛并转 `error` 事件 |

## 10. 计划中的接口（M2，未实现）

WebSocket 服务端将复用项目早期设计的单连接消息协议（一条连接承载所有消息，用 `type` 字段路由）：

| 消息 `type` | 方向 | 主要字段 |
|------------|------|---------|
| `text` | 客户端 → 服务端 | `content` |
| `audio` | 客户端 → 服务端 | `data`（16k PCM/float32）、`sample_rate` |
| `reply` | 服务端 → 客户端 | `content`、`audio_url`、`latency_ms` |
| `control` | 双向 | `action`：`interrupt` / `start` / `stop` |
| `error` | 服务端 → 客户端 | `code`、`message` |

> 该协议在 M2 实现后补充字段级说明与示例报文。
